# 面向结果的执行

优化目标是有意图的、可验证的最终状态，而不是维持平滑的中间状态。

**原因：** 让每个中间步骤都保持完全稳定，往往会产生临时兼容代码，这些代码会变成长期债务。应向目标架构收敛，并在明确的验证边界处证明正确性。

**核心规则：**
- 优先保证最终状态的完整性，而非过渡期的稳定性
- 当中间阶段的破坏是计划内的、有范围限定的且可回滚时，这是可以接受的

**防护措施：**
- 仅用于有明确阶段边界的计划性重写和迁移
- 声明允许临时破坏的位置
- 在迁移期间，对正在修改的区域保留高信号检查
- 在计划完成时，要求完整的静态和运行时验证
