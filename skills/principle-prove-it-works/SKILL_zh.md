# 证明它有效

在 Claude Code 中，每个会话开始时请先阅读一次 [Claude Code 适配器](../../docs/harness/claude-code.md)，再遵循本 skill。它会把 pstack skills 中的 Cursor 名称映射到 Claude Code。

逐一直接检查真实的内容来验证每个任务的输出。不要根据代理指标、自我报告或"能编译"来推断。

**原因：** 未经验证的工作，其正确性是未知的。间接验证（文件修改时间、输出新鲜度、代理的自我报告、缓存的截图）看起来比直接观察更省事。基于错误推断采取行动，代价远高于直接检查源头。

检查真实的内容，而不是代理指标：
- 直接检查进程是否存活，而不是通过派生状态间接判断
- 读取实际值，而不是缓存或派生的表示
- 验证失败时，先怀疑观察方法，再怀疑系统本身

## 尽可能把检查写成脚本

最有力的证明是一个确定性脚本，它可以重复执行相同的比较，而不是一次性的肉眼检查。编写脚本，运行它，并把输出保存为审阅者可以重新运行的产物，而不是只依赖你的陈述。

把产物保持对人类可见。只有在大型或复杂的工作中（例如大型移植或迁移，需要日后可审计的轨迹）才提交它（即 **show-me-your-work** skill）。
