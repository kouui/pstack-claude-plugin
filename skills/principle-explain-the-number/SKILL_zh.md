# 解释这个数字

- **问"为什么不是两倍？"** 指出限制结果的资源或代码路径，例如某个核心、某把锁、磁盘、网络，或负载生成器本身。通过性能分析或运行期间采集的系统计数器获得证据，再映射到源代码。仅凭阅读代码得出的猜测不算限制因素。如果你说不清为什么这个数字没有好两倍，你就不知道自己测的是什么。
- **列出这个数字还可能在测量什么，并用证据逐一排除。** 常见的怀疑对象包括：错误、被跳过或被缓存的工作、从未执行的代码、未调优的一端（使用默认设置的一方）、噪声，以及端到端来看影响很小的一小部分。
- **把证据和数字放在一起保存。** 在笔记或关联的产物中记录运行次数、波动范围和限制因素。

对于性能数字，请使用 [benchmark-checklist](../benchmark-checklist/SKILL.md) skill 执行完整流程。对于评估结果，同样要对各次试验提出这些问题：每次运行是否都完成了任务，差距是否在各次试验和各个模型之间都成立，以及该场景是否重要。

如果数字背后的证据没有运行次数、没有波动范围或没有指明限制因素，或者节省的时间大于被修改部分所花费的时间，那么你就跳过了这一步。

与 [Prove It Works](../principle-prove-it-works/SKILL.md) 不同，后者检查的是输出是否真实。
