# Correct

操作者不断在本仓库中纠正代理犯的同样错误。修改仓库，让下一个代理不可能再犯这些错误。

假设每位贡献者都是一个代理：它只能看到自己打开过的文件，复制最近的示例，并走能通过编译的最短路径。设计仓库时，要让从单个文件看起来正确的改动，对整个仓库也正确。

## 找出错误类别

首先，阅读近期的提交、回滚、评审意见、代理指令文件，以及解释变通方案的注释。把错误归类。某类错误发生过两次，才算一个类别。

## 在能用的最高层级修复每个类别

1. **用架构消除它。** 让每份状态只有一个所有者，每项任务只有一种受支持的方式。隐藏内部实现，使错误的导入失败。用单一事实来源替换需要手动同步的列表。删除代理可能复制的旧方式和死代码。
2. **用类型强制执行，使错误状态无法被写入。** 如果错误代码仍能通过编译，就添加一个 lint 或 CI 检查，其错误信息要指明应使用的文件、类型或函数。如果该模式已经很普遍，则只在某次改动新增更多该模式时才失败。
3. **测试行为。** 修复或删除那些在其所检查的行为被破坏时仍然通过、或仅在内部实现变化时就失败的测试。
4. **最后才写文档或代理规则，且仅用于需要判断的情况。** 代理跳过它们时，不会有任何东西失败。

## 修复并证明

然后立即修复最频繁的类别，每个类别一次提交。证明每项新检查都能在真实的过往错误上失败。在本地和 CI 中运行同一条命令。例外情况需写在对应的那一行上，并附上原因、过期日期以及人工批准。

## 保留规则表

最后，在代理指令文件中保留一张表，把每条规则与执行它的机制配对。操作者纠正你时，修复错误并添加规则。如果规则已经存在但没有任何机制执行它，这就是重复错误，应在同一次改动中以最高层级修复。错误已不可能发生时，删除该规则。

**回复：** 每个类别及其证据、你选择的层级，以及为什么更高层级行不通。
