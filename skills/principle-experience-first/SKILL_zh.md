# 体验优先

当实现便利与用户愉悦感冲突时，选择愉悦感。

- 每个功能、控件和选项都必须有正当理由
- 少而精（三个打磨精良的功能胜过十个粗糙的功能）
- 先原型后承诺（设计决策用一次性 HTML 验证，比用正式代码验证成本更低）
- 把细节做到位（过渡、对齐、间距、反馈、错误状态）
- 收紧核心流程（每个功能都应服务于核心工作流，否则就应让路）

这里的用户是指使用成果的人。对于 UI，就是最终用户。对于库或内部 API，就是导入它的同事。接手维护代码的工程师同样是用户。请以同样的方式衡量他们的体验，并从他们的视角解释影响。

基础设施应服务于体验。基础设施思维决定工作的*顺序*，本原则决定*目标*。
