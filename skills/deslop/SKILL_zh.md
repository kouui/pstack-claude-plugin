# Deslop

删除 agent 在被要求的改动之外多加的代码。保持行为不变。保留任务需要的每一行。

处理文字用 **unslop**。想让一个全新的审查者检查注释，用 **no-comments**。

## 范围

使用调用方给出的文件或 diff。否则使用当前相对基础分支（默认 `main`）的 diff，包括工作区。只改动 diff 新增或修改的行。不要清理 diff 没有触及的代码。

## 要删除的内容

- **叙述性注释。** 复述下一行代码、描述这次编辑（"added"、"now we"、"fixed"），或标记代码本身已经显示出来的分段的注释。只有在注释记录了代码无法表达的原因时才保留：约束、取舍、针对某个已命名 bug 的绕行方案。
- **没有依据的防御性判断。** 针对类型、调用方或数据模型已经排除的情况所写的空值检查、`try`/`catch`、回退和默认值。真正的边界处的防御性判断要保留：用户输入、网络、磁盘、第三方的返回值。
- **无用的兼容路径。** 在没有调用方需要时仍让旧行为继续存在的 shim、标志、别名和回退。如果这次改动替换了某个 API，就迁移调用方并删除旧路径。
- **无关的改动。** 重新格式化、重命名、调整 import 顺序、顺手重构，以及任务不需要的新辅助函数。把它们还原。如果其中某项值得做，就作为单独的工作报告出来。
- **投机性代码。** 还没有调用方的参数、选项、抽象和分支。

## 步骤

1. 完整阅读 diff。对每个改动块，问一问任务是否需要它。
2. 删除或还原上面清单列出的内容。不要把能正常工作的代码改写成新的风格。
3. 如果删除某个防御性判断可能改变行为，就检查调用方或运行代码。仍然不清楚时，保留该判断并报告。
4. 运行覆盖被改动文件的最窄检查（测试、类型检查、lint）。修复清理造成的问题。
5. 用几行话报告你删了什么（按类别分组），以及你有意保留了什么和原因。

## 规则

- 不要改变行为。改变行为的清理是一项新的改动，需要单独的检查。
- 不要扩大范围。diff 之外的废料写进报告，不要写进 diff。
- 不要删除带有约束的注释，例如 `do not remove` 或 `talk to X before changing`。把这些交给 **no-comments**。
- 优先删除，而不是改写措辞。
