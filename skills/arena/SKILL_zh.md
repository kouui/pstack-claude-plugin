# Arena

在 Claude Code 中，每次会话遵循本技能前，先阅读一次 [the Claude Code adapter](../../docs/harness/claude-code.md)。它把 pstack 技能中的 Cursor 名称映射到 Claude Code。

在启动任何操作之前，先打开一个待办列表，每个阶段一项（Frame、Fan out、Cross-judge、Pick、Graft、Verify）。

## 阶段 A：Frame（框定）

每个候选方案都获得相同的提示词，因此提示词就是契约。

1. 说明每个候选方案要产出的产物。
2. 推导评分标准，给出 3-6 条具体、可打分的标准，描述*本任务*的成功标准。它是阶段 D 中选择者使用的工具。候选方案只能看到任务本身。
3. 选择运行者。使用 `~/.claude/rules/pstack-models.md` 中的 `arena runners` 行。如果该规则或该行缺失，则默认每个使用一个 `opus high` 和一个 `sonnet high`。该行或 cross-judge 行中的 `auto` 或 `inherit-parent` 条目表示父模型，因此对其省略 `model`。如果 Task 工具拒绝了已配置的条目，则该席位改用其所属家族的默认模型，并说明这一点。家族按前缀划分：`claude-*`，以及 `grok-*`（包括 `cursor-grok-*` 和 `composer-*`）。被拒绝的 `composer-*` 条目改用 `sonnet high` 运行。没有匹配的家族时，使用 `opus high`。如果默认模型也被拒绝，则从其错误信息中选用同一家族中最接近的有效 slug。当竞技场涵盖多个设计方向时，启动更多运行者。当工作以生成为主而非依赖判断时，对 N 次使用同一模型。根据 **poteto-mode** 技能的 Subagents 一节，为每个子代理选择其推理级别以及快速或标准速度，以适配该工作。
4. 为每个候选方案分配其独立的输出位置（尽可能使用 git worktree，否则使用 `/tmp/arena-<slug>/candidate-<n>/`），遵循 **separate-before-serializing-shared-state** 原则技能。

## 阶段 B：Fan out（并行分发）

在一条消息中以 `run_in_background: true` 启动全部 N 个子代理，每个子代理都附带任务、共享依据的路径、其独立的输出路径，以及产出产物和一段简短理由的指令，理由中需说明它考虑过的备选方案以及它拒绝了什么。

如果某个候选方案没有产生输出，则以 N-1 个继续，并记录该掉线情况。

## 阶段 C：Cross-judge（交叉评判）

阶段 B 的所有候选方案完成后，从 `~/.claude/rules/pstack-models.md` 中的 `arena cross-judge pool` 行选择一个模型。如果该规则或该行缺失，则从 `opus high` 和 `sonnet high` 中选择。优先选择与父模型不同家族的模型。启动一个只读评判子代理，使用该模型。它会看到评分标准以及按路径标签列出的候选方案，为每条标准打分，并推荐一个基础方案及其理由。它与阶段 D 中你的阅读并行运行。候选方案仍在写入时不要启动它。

## 阶段 D：Pick a base（选定基础方案）

在选定之前，通读每个候选方案。按评分标准逐条打分，而不是凭整体感觉，并与 cross-judge 的结果比较。对基础方案的一致意见确认了选择。出现分歧则说明你们中有一方存在偏见，或者评分标准有歧义。在决定之前，阅读双方的理由。

选择未来维护者最容易扩展、又不会破坏不变量的基础方案。如果两者看起来相当，则依据 Laziness Protocol，优先选择边界更清晰或 API 更小的方案。

## 阶段 E：Graft（嫁接）

再次逐一检查每个失败的候选方案，找出值得移植到基础方案中的内容，通常每个候选方案一两项，而不是大部分内容。依据 **redesign-from-first-principles** 原则技能，手工将每项嫁接融入，使结果在同一个心智模型下保持连贯。不要机械地粘贴。

如果候选方案收敛到同一形态，这就是强烈的一致性。记录下来并交付该共识形态。不需要嫁接。如果它们差异极大，则说明阶段 A 的规定不够充分。重新框定并再次运行，而不是对分歧取平均。

## 阶段 F：Verify（验证）

依据 **prove-it-works** 原则技能，像验证其他任何产出一样验证合成的产物。如果验证发现了 arena 遗漏的问题，则要么阶段 A 有误（重新框定并再次运行），要么某个候选方案发现了它而你遗漏了对应的嫁接（回到阶段 E）。不要掩盖它。

## 输出

一个合成的产物，附带一份简短的合成说明，内容包括：基础方案及选择理由、cross-judge 的结论、每项嫁接及其来源候选方案、被拒绝的内容及理由、任何收敛或掉线情况，以及验证结果。
