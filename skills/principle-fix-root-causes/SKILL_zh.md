# 修复根因

调试时，修复的是故障本身，而不是故障显现的地方。症状是错误状态变得可见的位置。根因则是系统第一次做了本不该做的事，或未能处理本应处理的状态的地方。

**原因：** 对症状的修复会掩盖证据，并让故障有机会在别处再次显现。每一次这样的修复都会让系统更难推理，因为代码现在携带着一个针对某个没人指出的 bug 的变通方案。

**方法：**
- 先复现。
- 在每一步都追问“为什么”，直到答案是代码中一个错误的决策，而不是更早某个问题的后果。
- 陷入困境时，进行插桩。读取实际的错误和实际的状态。不要猜测。
- 追问触发该症状的状态是否合法。如果系统可能处于该状态，那么在它上面出错的代码就是根因，在那里处理该状态就是修复。如果该状态本不应该存在，那么在出错处加一道检查只会掩盖 bug。要找到是什么产生了这个状态。守卫、重试、被吞掉的错误、被钳制的值以及被丢弃的状态，是隐藏 bug 的常见手段。
- 当某件事只在重启之后才失败时，首先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。
- 检查的是模式，而不只是单个实例。找出所有存在同样故障的位置，并全部修复。
- 如果一个变通方案需要一大段注释来为其辩护，那么代码就是错的。应修复代码，而不是注释。
- 如果找到决定性事实花费了一番深入挖掘，就提议一个低成本、始终开启的信号，它在第一眼看上去时就能揭示该事实。
