# Notes 验证地图

本目录是验证 Notes 面向用户行为的维护源。在驱动应用之前请先阅读索引,然后将对应的功能文件作为操作指南使用。

## 基线前置条件

- 在 `http://127.0.0.1:4173` 启动 Notes,并使用一次性数据目录。
- 设置 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`,以确保并发运行不会共享状态。
- 植入标题为 `Quarterly plan` 和 `Grocery list` 的笔记。
- 将 `control-notes` 和 `notes` CLI 放入 `PATH`。
- 运行 `control-notes doctor`,并要求其输出预期的 URL、数据目录和构建版本号。
- 绝不要驱动非本次验证运行所启动的实例。

## 驱动约定

- 除非前置条件另有说明,每个操作指南都从基线状态开始。
- 优先使用 ARIA 角色和可访问名称,而不是 CSS 选择器或 DOM 位置。
- 将每条命令视为字面量。保持带引号的名称和参数不变。
- 通过 `control-notes browser` 执行浏览器操作。
- 通过 `control-notes cli -- <command>` 执行终端操作。
- 在变更后恢复植入的数据。清理时不要删除证明性产物。

## 证明与跳过记录

- 同时记录用户操作以及由此产生的状态,而不只是最终屏幕。
- UI 证明包括 ARIA 快照,以及一张可见应用标识的截图。
- CLI 证明包括命令、stdout、stderr 和退出码。
- 变更证明包括对已存储值的只读第二视图。
- 每个产物都要记录所使用的功能 ID 和入口点。
- 对于无法到达的路径,请记录所尝试的命令以及未满足的前置条件。
- 不要将已跳过的入口点报告为通过其他路径验证过。

## 功能条目约定

每个功能文件以一个 H1 标题和一段描述用户可见行为的段落开始。随后按顺序恰好使用四个 H2 小节。

1. `Sub-features` 列出简短 ID,每个行为占一行。
2. `How to get to it (user POV)` 列出每个用户入口点。
3. `Driving it with <harness>` 以 `Preconditions:` 开头,并使用带标签的列表项,将每个用户操作与一条精确命令及可观察结果配对。
4. `Gotchas` 列出可能浪费或使验证运行失效的陷阱。

请将实现细节排除在地图之外。只写明用户路径、稳定句柄、所需状态、命令以及可观察的证明。

## 功能

- [Create a note](./create-note.md) 涵盖浏览器与 CLI 创建、取消、持久化以及清理。
- [Search notes](./search.md) 涵盖工具栏、键盘和 CLI 搜索,包括匹配、空结果和清除状态。
