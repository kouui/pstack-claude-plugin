# 构建杠杆

当工作并非平凡时，构建能完成它的工具，而不是手工完成。

codemod、生成器或脚本每次都以相同方式完成工作，并且可以免费重新运行。该工具是评审者可以阅读和重新运行、用以检查工作的一个产物。手工完成的改动只能通过重做来重新验证。确定性的脚本能把"相信我"变成"运行这个"。

默认构建这个杠杆。只有在任务平凡、即几处一眼就能看出的明显编辑时，才可以跳过。

- 先手工完成第一个单元，以学习方法，然后构建该工具。通过在该单元上重新运行它，并与你手工完成的版本做 diff 来证明它。让这个杠杆可以安全地重复运行。
- 编辑用 codemod 或脚本，重复性文件用生成器，分析用 dump-to-sqlite 查询，验证用可重复运行的检查。
- 确定性的杠杆优于扇出。如果工具能一次处理所有单元，就由你自己运行。不要为了手工应用脚本就能完成的事而扇出给代理。
- 将工作扇出给子代理时，把这个杠杆写成所有子代理都会读取的 skill：配方、验证约定和禁止触碰的边界，都放在同一个产物中。将它放在代理的写入范围之外，使它们不能悄悄修改约定。
- 应用此原则会产生一个文件。如果你引用了它，而 diff 中没有 codemod、脚本、生成器或委派用的 skill，那么你就没有应用它。
- 当工作超出本次会话的生命周期时，提交这个杠杆。

判断标准是平凡性，而不是重复性。一次性的工作，只要杠杆能让它可检查，仍然值得构建杠杆。依据 [懒惰协议](../principle-laziness-protocol/SKILL.md)，构建完成或证明该工作的最小脚本，绝不构建框架。

它不同于 [将经验编码进结构](../principle-encode-lessons-in-structure/SKILL.md)，后者把重复出现的指令变成持久的防护机制。本原则关注的是手头工作的吞吐量和可评审性。关于验证本身的脚本编写，参见 [证明它有效](../principle-prove-it-works/SKILL.md)。
