# 攻击前提

当两个或更多共享同一前提的修复都未通过同一道关卡时，怀疑的是前提，而不是修复本身。

**原因:** 每一次失败的修复都是对其所依据的信念的证据。在同一前提上再写第三个修复，是把精力投入到证据已经表明并非原因的地方。

**模式:**
- **把前提写下来。** 前提是每一次失败修复都依赖的那一句话。
- **在下一次修复之前测试前提。** 找到一个观察结果，它在前提为假时会呈现不同的结果，然后去做这个观察。不仅要看失败的规模大小，还要看失败的分布情况。按照 [Build the Lever](../principle-build-the-lever/SKILL.md) 的要求，使这个检查可以重复运行。
- **遵循证据。** 如果证据与前提相矛盾，原因就在别处。寻找这些失败的共同点，而且这些共同点是前提没有预测到的。如果证据证实了前提，则按照 [Fix Root Causes](../principle-fix-root-causes/SKILL.md) 继续追问下一个"为什么"。早先的修复可能只是处理了结果，而不是原因。
- **移除条件，而不是补偿它。** 依据 [Laziness Protocol](../principle-laziness-protocol/SKILL.md)。如果证据表明某一部分总是落在失败的一方，就去改变使它落到那里的原因。一个在之后清理残局的机制会让原因保持不变，并在每次运行时增加额外工作。

**停止:** 在前提被写下并经过测试之前，不要开始下一次修复。

本原则不同于 [Redesign from First Principles](../principle-redesign-from-first-principles/SKILL.md)，后者是围绕新需求重建设计。本原则质疑的是当前设计所假定的某个事实。
