### 会话接续

**你负责续接点。读取之前的记录，不要重做。**

1. 定位之前的记录。可以是当前工作区 `agent-transcripts/` 目录下的本地转录文件（系统提示会给出路径。不要跨 `~/.cursor/projects/*/` 进行 glob 搜索，那样会跨越工作区边界，读取无关项目的私人对话）或是已推送的分支。先阅读元数据概览和最后几条消息，然后回溯扫描关键决策点。如果转录很长，在子 agent 中解析，并在主线程中保留精简后的时间线（**principle-guard-the-context-window** 技能）。按照子 agent 部分的说明，为每个子 agent 选择合适的推理级别以及快速或标准速度。
2. 重建运行状态。包括分支和 worktree、已经合并的内容（`git log`，与基线做 `git diff`）、未完成的待办事项、已做出的决策。之前的记录是权威输入。要克制重新推导它的倾向。
3. 对比已完成与待完成。将已交付的内容与计划内容进行比较，指明续接点，不要重新运行之前的复现，也不要重做已完成的工作。“让我从头验证一遍”的做法，等于把本应可信的记录当作不可信，这是错误的。
4. 将剩余工作路由到匹配的 playbook，并选定结论：继续执行、交付已完成的建议、确认或推翻之前的结论，或对失败的运行进行复盘。接续 playbook 到此结束。后续由被路由的 playbook 负责。
5. 在真实产物上，依据原始目标验证继承的结论（**principle-prove-it-works** 技能）。之前的自我报告通过，并不构成证明。

**回复：** 说明之前的 agent 停在何处、继承了什么与重做了什么（最好是什么都没重做）、续接点，以及结果。
