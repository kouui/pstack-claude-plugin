### Eval

**你负责实验设计。规划、盲化、运行、综合。**

**盲化的不可协商要求:**

- 候选者能看到的任何目录、文件或提示中,都不得出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 候选者的提示应像一个有机的用户请求。说明目标,不说明元信息。
- 不要有引导链式行为的暗示。不要要求候选者列出它应用了哪些 skill、原则或文件。请泛泛地询问设计说明,并根据代码结构而非自我报告来评判其是否遵循了链式流程。
- 对目录和 slug 名称进行清理。使用用户可能会选择的、符合项目风格的名称。
- 不要告诉候选者存在其他候选者。
- 评审者可以知道自己在做评审,但只能通过清理后的标签看到输出,绝不能看到模型名称。
- 比较两个变体时:由一位评审在单一量表上一次性为两组输出打分,且评审不知道每组来自哪个变体。

**步骤:**

1. **定框架。** 说明被测变体是什么,以及什么行为算作成功。仅为评审编写评分标准(3-6 条具体标准),并对候选者保密。
2. **搭建清理后的环境。** 为每个候选者准备一个工作目录,并在其中放入该变体。植入有机任务中自然会有的上下文:项目骨架,以及候选者自然会去读取的 skill。
3. **编写一条有机的提示。** 即用户会输入的内容。不要泄露被测的内容。
4. **并行生成 N 个候选者**,模型各不相同,依据 **arena** skill 的阶段 B 执行。每个候选者在其各自清理后的目录中工作。向每个候选者发送相同的提示。按照 Subagents 一节,为每个子代理选择适合该任务的推理级别以及快速或标准速度。
5. **生成一名盲化评审**,其模型系列与候选者不同,依据 **arena** skill 的阶段 C 执行。评审只能通过清理后的标签看到输出,并看到评分标准,绝不能看到模型名称。
6. **从对话记录而非自我报告中验证链式行为。** 读取每个候选者在当前工作区 `agent-transcripts/` 目录下的本地对话记录(系统提示会指明该路径)。不要跨 `~/.cursor/projects/*/` 进行 glob 搜索。那样会跨越工作区边界,读取无关项目的私人聊天记录。查看每个候选者实际打开了哪些文件。仅根据它真正读取的文件以及代码的结构来评判链式行为,绝不依据候选者自己的声明。
7. **亲自通读每个候选者的全部输出。** 将其与评审的结论进行比较。如果两者不一致,说明某个模型存在偏差,或者评分标准有歧义。然后进行综合。

**回复内容:** 被测变体、评分标准、每个候选者的笔记、评审的结论、你的综合意见,以及关于是否推广该变体的建议。
