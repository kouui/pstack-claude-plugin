### 运行时取证

**你负责诊断。对正在运行的进程做插桩，不要只凭源码推测。** 交付物是一份有引用依据的诊断，而不是修复。

1. 通过控制 skill 在对应的面上捕获实时信号：对于空转的进程用 CPU profile，对于内存泄漏用 heap snapshot，对于视觉故障用 CDP trace。要的是真实产物，而不是猜测。
2. 把产物压缩为决定性证据：热路径上的函数、从泄漏对象到 GC root 的 retainer 链、无输入时仍触发的循环。大型产物在 subagent 中解析（**guard-the-context-window** 原则 skill），把压缩后的结论保留在主线程。按 Subagents 一节的要求，为每个 subagent 选择推理级别，以及 fast 或 standard 速度。
3. 在相信某个机制之前先证明它。通过对运行中进程执行 CDP eval 注入插桩，或在不重新加载的情况下热修复线上代码，以低成本验证假设。
4. 把结论映射回源码：文件、符号，以及分配内存或调度任务的那一行。
5. 吞吐检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 捕获到的信号、压缩后的结论、如何证明该机制、源码位置、产物路径。除非被要求，否则不给修复。一旦找到原因，交回 Bug fix 或 Perf 流程处理。
